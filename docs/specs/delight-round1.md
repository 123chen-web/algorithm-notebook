## 设计原则（用户明确要求）

用户的原话：“实用高效又不是那么老套，让人不想点进来的网站不行；多给人带来情绪价值，加点动画和互动。”

1. **有性格，不堆砌。** 这个站的气质是“水墨 × 红笔批改”（栖间主题是另一套绿色山水）：纸张、印章、墨迹、批注。动效都从这个世界里长出来——盖章、墨晕开、纸张翻动、山水生长。**不要**通用的彩色五彩纸屑、渐变光晕、满屏 emoji、弹窗式“恭喜你”。克制、精致、有一点点惊喜。
2. **借鉴，但别照抄。** 调研到的值得借鉴的点：
   - Duolingo 的连续打卡：里程碑像“升级”而不是一个数字；但也有人批评它的“愧疚式”文案。**我们取其里程碑仪式感，不取愧疚**——断了不惩罚，只是墨色淡一点。（[设计与心理分析](https://japm.substack.com/p/the-psychology-behind-duolingos-most)）
   - Forest 的“种树成林”：成果沉淀成一片会生长的画面，比分数更有情绪。（[分析文章](https://uxplanet.org/what-to-learn-from-the-forest-apps-gamification-5d8fe48eb4f4)）
   - 黄历类应用：信息分层（默认少，点开才有“为什么”）、纸质质感、翻页/撕页的仪式感、娱乐性免责声明。
   - GitHub 无障碍团队对拖拽的结论：**拖拽是高风险交互**，必须同时提供键盘和“点选”替代方案。（[GitHub 博客：可访问的拖拽排序](https://conffab.com/elsewhere/exploring-the-challenges-in-creating-an-accessible-sortable-list-drag-and-drop-the-github-blog/)）
   - 实现上：Pointer Events 统一处理鼠标/触摸/笔；**不引入第三方拖拽库**（本站严格 CSP、没有构建步骤），自己写一个小的状态机即可。
3. **每个动效都要有“关掉的版本”**：`prefers-reduced-motion: reduce` 下全部改成无动画的即时状态；手机低端机不卡（只动 `transform` / `opacity`，页面不可见时暂停循环动画）。
4. **主题**：水墨红笔和栖间两套都要好看，颜色只用主题变量（`var(--ink)` `var(--accent)` `var(--surface)` …），不要写死色值（有测试会拦）。
5. **硬规则**（和之前任务相同）：严格 CSP（不写行内 style、不用 innerHTML 拼用户文字、不用 eval）；测试里不真调用 AI/发邮件；不在项目目录建临时目录；改了静态资源要同步 `?v=` 和测试里的版本 pin；数据库迁移号从 **78** 开始并且幂等；全量 `PYTHONUTF8=1 python -m pytest tests -q -p no:cacheprovider --ignore=tests/e2e` 全绿（本机 `.claude` 目录引起的 `test_billing_docs_consistency` 误报除外）；前端行为要有测试（参照 `tests/*_behaviour.cjs` + `tests/js_harness.cjs` 的假浏览器写法）。
6. **每一项单独交付**（单独一个 zip，带 REPORT）：先做 ①，再 ②③④。每项报告里贴 1–2 张截图（桌面 + 手机宽度，两套主题）。

## ① 套路分类桶（把题目丢进桶里）★ 最优先

### 背景
学习路线里每道错题要归到套路上，但用户自己判断很吃力。我已经做好了**自动猜的引擎和接口**（`pattern_match.py`、`routers/roadmap.py`），你来做界面。把“分类”做成一个好玩的小游戏。

### 我已经提供的接口（都要登录；写操作要 `X-CSRF-Protection: 1`）
- `GET /api/roadmap/inbox?limit=30&offset=0` → `{total, items:[{problem_id, title, snippet, source_url, created_at, tags:[…], suggestions:[{pattern_id, title, category, score, reason}]}]}`：待分类的题（算法分区、还没归任何套路），每道带最多 3 条建议，`score` 越高越可信（100=链接就是该套路的例题，80=题名和例题相同，60/50/45/40=关键词/别名/标签/思路）。
- `POST /api/roadmap/suggest` `{title, thinking?, source_url?, zone?, tags?[]}` → `{suggestions:[…]}`：新增记录页边写边猜。
- `PUT /api/problems/{id}/patterns` `{pattern_ids: [最多3个]}` → `{ok, problem_id, pattern_ids}`：归类（全量替换，传 `[]` 就是移出分类）。
- 套路清单是静态文件 `static/data/patterns.json`（150 个，字段 `id/title/category/level/…`），前端可以直接读，分类桶就从它的 `category` 生成（约 25 个大类）。`GET /api/roadmap` 里有 `progress` 和 `mistake_counts`。

### 要做的界面
1. **待分类箱（新视图）**：学习路线页顶部出现“你还有 N 道题没分类 →”（N=0 时不显示，或显示一个“全部分好了”的小印章），点进去是分类场景：
   - **左边（手机在上方）一摞题目卡片**（题名 + 一句思路 + 来源徽标），像一叠待批的卷子，最上面一张是当前题；
   - **右边（手机在下方，横向可滚动的一排）是“桶”**，每个桶是一个大类（数组、双指针、二分、动态规划、图论……），带小图标、类别名、里面已有几道；
   - **把卡片拖进桶里**。系统猜得有把握的桶（建议里的 `category`）**微微发光**并轻轻“呼吸”，提示“可能是这里”；
   - 放进大类桶后，弹出一个小气泡让用户选这个大类里**具体是哪个套路**（建议里命中的那个高亮、排第一，点一下就好；也可选“先放大类，具体套路以后再说”）——确认后调用 `PUT /api/problems/{id}/patterns`；
   - **盖章反馈**：卡片落进桶的瞬间，桶沿“盖”上一个小红印并带一点点墨晕；顶部显示“还剩 3 道”；全部分完出现一个完成的大印章和一句话。
   - 有**撤销**（底部一条淡淡的提示：“已放入「二分」· 撤销”，5 秒内可撤）。
   - 卡片可以“跳过”（放回牌堆底部）。
2. **同样的数据，三种操作方式，缺一不可**：
   - 鼠标/触摸**拖拽**（Pointer Events；拖起时卡片略放大倾斜，桶有吸附感，松手弹簧回弹或落入；不要用 HTML5 原生 dragstart，触屏不可靠）；
   - **点选**：点一下卡片（选中高亮），再点一下桶；手机上这是主要方式；
   - **键盘**：卡片获得焦点后 `空格/回车` 拿起，`←→/↑↓` 在桶之间移动，`回车` 放下，`Esc` 取消；每一步用 `aria-live` 播报（“已拿起《过河卒》，当前在桶「动态规划」，按回车放下”）。
3. **新增记录页**：把现在那个很长的“属于哪个套路”列表**替换**成一行“可能属于：滑动窗口 · 双指针”的小标签（输入题名/粘贴链接后防抖 400ms 调 `POST /api/roadmap/suggest`，点一下加入，最多 3 个，已选的可以点掉），旁边留一个很小的“手动选择”折叠入口（保留原来的搜索选择器，放进折叠区）。**不选也不影响保存**，没选的自动进待分类箱。编辑题目弹窗里的手动选择器保留不动。
4. 学习路线页的套路卡片“你记过 N 道错题”徽标，点它跳到该套路的分类结果（有这个入口就行，列表筛选可简单做）。

### 验收
- 三种操作方式的行为测试（拖、点选、键盘）、撤销、接口失败回滚、晚到响应丢弃（参照 `recommend.js` 的 `ticket()/current()` 写法）。
- 桌面和手机（≤520px）都可用；两套主题；减少动画下无动效。
- 没有数据（待分类为 0）、只有 1 道题、建议为空这三种空状态都有好看的呈现。

## ② 山水成长背景（总览页）

**要什么：** 总览页顶部（“今日一签”上方）一幅**会生长的水墨小山水**（栖间主题是对应的绿色山水）。用户每**掌握**一个套路（学习路线里状态为“已掌握”），画面就多长出一点东西：远山多一层、近处多一棵树、一只飞鸟、一叶扁舟、水面多一圈涟漪……满额时出现日出/满月。它是用户学习成果的“活的画”。

**数据：** `GET /api/roadmap` 的 `progress`（`{pattern_id: "learning"|"mastered"}`）和 `static/data/patterns.json`（总数 150）。用“已掌握数 / 总数”决定整体阶段，具体长出哪些元素由**套路 id 的哈希确定且稳定**（同一个套路永远对应同一个元素，位置不乱跳）。

**要求：**
- 纯 SVG（`createElementNS` 构建），不用图片；整幅画 ≤ 约 40 个元素；两套主题各一套配色（走主题变量，必要时在 CSS 里给 SVG 元素上色）。
- 空画面（一个都没掌握）不能难看：只有一座淡淡的远山和一行“学会第一个套路，这里就会长出第一棵树”。
- **“新长出来”动画**：当用户刚把一个套路标成已掌握后回到总览，那个新元素用“墨晕开”（`opacity`+`transform: scale` 从小到大，带一点点墨色外扩）长出来；只播一次（记 `localStorage`，读写失败也要能用）。
- 轻微常驻动画（只在页面可见时）：薄雾缓慢飘、飞鸟偶尔掠过、水波很淡；`prefers-reduced-motion` 下全部静止。
- 点（或悬停/聚焦）画面里的元素，显示一句“因为你掌握了「二分查找」”；键盘可聚焦、有 `aria-label`。
- 画面下面一行小字进度：“已掌握 12 / 150 · 再学 3 个，远山将多一层”（别写成压力式文案）。
- 不要阻塞首屏：`/api/roadmap` 失败或慢时先显示静态占位。

## ③ 复习手感升级

**要什么：** 让复习从“点按钮”变成有手感的小游戏。现有评分流程（先回忆、再看错因、再打分）和接口**不要改**，只加交互层。

1. **翻牌**：点“显示错因”时，卡片做一个纸张翻面（`rotateY`，背面是错因；只动 transform，`backface-visibility`），而不是内容硬切。
2. **滑动评分**（触摸 + 鼠标拖拽，Pointer Events）：把卡片向右拖 = “记得”，向左拖 = “忘了”，向上拖 = “很熟”（具体对应现有评分档位，请先读现有评分按钮和接口，保持一致，并在 REPORT 里写清映射）。拖动时卡片跟手、略旋转，边缘出现渐变的提示字（“记得”/“忘了”），超过阈值松手才提交，没过阈值**弹簧回弹**；提交后卡片飞出，下一张从下面轻轻升起。原来的评分按钮保留（滑动是增强，不是替代），键盘用户不受影响。
3. **盖章反馈**：评分成功后，卡片角上“盖”一个对应的小印（记得=红印，忘了=墨印），0.3 秒，不挡操作；已有的撤销要继续可用。
4. **触感**：支持的设备上，成功评分时 `navigator.vibrate(10)`（只在用户手势里触发），并在账号设置里加一个“震动反馈”开关（默认开，存 `localStorage`）。
5. **专注模式**（`static/focus.js`）同样接入翻牌和滑动。
6. 注意**防误触**：纵向滚动页面时不能误触发横向滑动评分（用方向锁定：先判断手势主方向再决定接管）。

## ④ 打卡墨点（替换“连续打卡”的数字卡）

**要什么：** 总览页现在有一张“连续打卡 N 天”的卡（数字 + 一排小圆圈）。把它做成**墨点**：

- 一滴墨落在宣纸上，**连续打卡越久，墨点越大、越浓、边缘越多“晕开的毛边”**（SVG 滤镜或多层圆叠加，别用位图）；
- 今天**第一次完成复习**的瞬间，播放“墨滴落下”：从上方落下一个小墨点，砸在大墨点上，涟漪一圈圈扩散（≤ 1 秒，只播一次，记 `localStorage`）；
- **断了不惩罚**：中断后墨点不归零，而是“墨色变淡、缩小一档”，并给一句温和的话（“墨还在，再点一下就回来了”）；连续天数的数字仍然清楚显示（无障碍和一眼可读）；
- 里程碑（7/30/100 天）墨点边上盖一个小印并有一句“里程碑”文案，仪式感而不是五彩纸屑（参考 Duolingo 的“里程碑如同升级”，但不要愧疚式文案）；
- 数据用现有的连续打卡接口/字段（读代码找到“连续打卡”卡片用的数据，不要新增迁移）。
