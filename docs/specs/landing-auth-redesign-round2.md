## 必须修（验收中发现，违反"多余提示尽量去掉"）
### R1. 体验账号登录后的提示重复
进入学习大厅后，标题上方连续出现两条几乎相同的提示：
- `#trial-banner`："这是体验账号，数据可能会被定期清理，注册正式账号才能长期保存。"
- 一条 info 提示："已进入体验账号，随便试试看吧——数据可能会被定期清理。"
要求：只保留**一条**，且不占据大厅首屏高度（做成头像/账号区里的小标记或可关闭的细条均可，关闭后同一会话内不再出现）。保留 `#trial-banner` 的 `role="status"` 语义；既有测试若依赖文案，请同步调整并在说明里列出。

### R2. 学习大厅顶部过高
大厅标题上方堆了：头部品牌卡片、账号/额度卡片、提示。1280×800 要滚动才能看到入口卡片，手机更严重。
要求：品牌、账号、额度合并为**一行**（手机允许两行：品牌/账号一行，额度折进头像菜单或细进度条）；1280×800 与 390×800 下，学习大厅标题和至少第一排入口卡片都在首屏内。不得删除额度信息（只能收纳）。

## 流畅度（用户要求"帧率最好高一点"）
### F1. 先量后改
用真实浏览器（不是无头软件渲染）在桌面和手机宽度下，分别测：背景涟漪空闲、涟漪播放中、轮播切换瞬间的 `requestAnimationFrame` 实测帧率和最长单帧耗时。把测量方法和数据写进最终说明。
### F2. 消除已知卡顿来源
- 控制台出现过 `GPU stall due to ReadPixels`：找出 `static/cursor-fx.js`（或能力探测代码）里的 `readPixels` 调用，确认是否在动画期间触发；若只在初始化探测时调用，则移到空闲时或改为不阻塞渲染的方式。
- 桌面：目标是在 60Hz 屏上稳定 60fps，在 120/144Hz 屏上不人为限帧（现在桌面没有限帧，保持）；若测得掉帧，按"降低分辨率缩放 → 降低 DPR 上限 → 减少同屏波纹数"的顺序调参，每次调整记录前后数据。
- 手机：沿用既定决定——**静态图 + 轻微涟漪，不自动轮播**；触屏帧间隔上限（`RIPPLE_TOUCH_MIN_FRAME_MS`）可按设备刷新率放宽到 90Hz 以内，但不得提高发热/耗电，页面不可见时必须停止渲染。
- 轮播淡入淡出只用 `opacity`/`transform` 并配 `will-change`（切换结束后撤掉），不要触发布局或重绘大面积模糊。
### F3. 回归保护
`prefers-reduced-motion`、`backdrop-filter` 仅限 `(hover:hover) and (pointer:fine)` 的既有规则不得破坏；既有测试不改动，除非 R1 必须。

## 建议改进（做不做由你判断，但请在说明里写明做了/没做及原因）
- S1. 介绍页的风景应是主角：目前被左右两张大卡片挡住大部分。让预览卡变小或让出一侧，使风景至少占可见画面的 40%。
- S2. 轮播圆点栏在 800 高屏幕上被切掉一半：放进首屏。
- S3. 栖间主题目前只是换色换背景：按"左侧大标题 + 一句话，右侧一块面板，多留白"的方向调整**栖间下**的介绍页和大厅版式（水墨主题保持不变）。

## 不要做
不动后端/数据库/支付/AI；不新增依赖；不改既有测试（R1 例外）；不在项目目录创建临时/缓存目录。

## 验收（Claude 会逐条核对）
1. 体验账号登录后只剩一条提示，大厅首屏（1280×800、390×800）能看到标题和入口卡片。
2. F1 的实测数据在说明里；桌面空闲/播放中无明显掉帧，`ReadPixels` 警告在动画期间不再出现。
3. 手机静态首图 + 轻微涟漪不变，页面隐藏时渲染停止。
4. 两个主题、六个宽度（1280/1024/800/390/360/320）无横向溢出。
5. 全量 `pytest -q` 通过（云端缺支付 SDK/中文字体除外）。
