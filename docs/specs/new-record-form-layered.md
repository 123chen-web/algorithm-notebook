# 第四轮需求：「新增记录」页改成长页分层卡片（方案 B）

用户已在对比稿中选定**方案 B：长页分层卡片**。本轮只改「新增题目记录」页（`#new-page`）的排版与交互细节，不扩大范围。
约定同前：遵守 `AGENTS.md`（系统临时目录不可写时先停下来报告，不要在项目目录建临时目录）；按编号 F1→F4 各自单独提交；完成后推送到 `main-lxh6n1`。

## 背景与目标
现状（手机截图）：原生文件选择框又丑又大；所有区块平铺在同一底色上，只靠一条细线分隔，看不出"层"；每段都带说明文字，字重相近，显得又密又平。
目标感觉："层次分明、很丝滑"——大留白，卡片分层，信息有主次，过渡柔和。
参考（只借思路，不引入依赖；均为 MIT）：shadcn-html 的表单字段间距、`::file-selector-button` 文件框、聚焦光圈、steps 进度条；见对比稿 `form-options.html` 的方案 B。

## 必须保留（硬约束）
- 现有全部 id、`name`、`required`/`maxlength`/`minlength`、`accept`、`aria-*` 与表单提交逻辑不变；`#problem-photo-form` 与 `#problem-form` 仍是两个独立 `<form>`，AI 识别、额度显示、`data-blocked` 忙碌禁用、预览、移除图片、保存识别结果等行为完全不变。
- 原生 `<input type="file">` 必须保留（可访问性与移动端相机/相册），只做样式与拖放增强，**不要用 `display:none` 隐藏它**（可视觉隐藏但保持可聚焦）。
- 两个主题（`ink` 水墨 / `qixi` 栖间）都要好看：颜色、圆角、阴影全部走现有 CSS 变量，不写死色值、不复制两份样式。
- `backdrop-filter` 仅允许出现在 `(hover:hover) and (pointer:fine)` 媒体内，半透明背景需 `@supports` 回退（见 `tests/test_cursor_fx_assets.py`）。**不要为过测试改测试。**
- `prefers-reduced-motion` 下取消所有过渡/动画；过渡只用 `opacity`/`transform`/`box-shadow`/`border-color`，时长 150–220ms，使用 `--motion-ease`。
- 桌面 ≥1024px 现有"左侧小标题 + 右侧字段"的两栏布局保留并融入卡片（卡片内左右两栏），不要退化成单栏。

## F1. 分层卡片与层次
- 每个区块（AI 上传、01 题目和代码、02 回想当时的思路、03 错误原因，以页面现有区块为准）做成独立圆角卡片：白/纸色底、细边框、轻阴影，卡片间距 ≥ 14px，页面背景与卡片有明显色差。
- 卡片头：左侧**编号徽标**（圆角方块，淡强调色底），右侧**标题（粗）+ 一句话说明（淡色、小一号）**。把现有较长的说明压缩成一句，长说明（如额度、格式限制）降级为更小的辅助行。
- 字段：标签小而粗，输入框 ≥ 44px 高、圆角 12px、内边距充足；聚焦时边框变强调色并出现柔和光圈（`box-shadow` 过渡）；字段之间统一 16px 垂直间距；去掉各区块之间的 `border-top` 细线（卡片本身已分层）。
- 页面顶部加一条**细进度条**（随当前滚动到的区块高亮，纯展示，`aria-hidden`），桌面可不 sticky；手机 sticky 在顶部。

## F2. 上传区改造（只改外观与拖放，不改逻辑）
- 原生文件框换成**拖放区**：虚线圆角框、图标、"点这里选一张图片"主文案、"JPEG / PNG / WebP · 最大 8 MiB"辅助文案、一个主按钮「选择图片」。整块区域可点击（用 `<label for="problem-photo-file">` 包裹），键盘 Tab 可聚焦并显示焦点环。
- 桌面支持把图片拖进来（`dragenter/dragover/drop`，拖入时高亮；把 `dataTransfer.files[0]` 赋给 input 后派发 `change` 事件，复用现有逻辑；不是图片或超限时沿用现有提示，不新增校验分支）。
- 选择图片后：预览图在拖放区内显示（现有 `#problem-photo-preview`），文件名显示，原"移除图片""识别并填入表单"按钮保留在拖放区下方，层级清楚（识别为主按钮，移除为次按钮）。
- 额度/失败计数说明收成一行小字，不再占一个段落。

## F3. 折叠与摘要（降低一页的压迫感）
- "02 回想当时的思路"和"03 错误原因"（及之后非必填/较长的区块）默认折叠成**一行摘要卡**：编号 + 标题 + 状态徽标（"待填写"/"已填写"）+ 展开箭头；点击展开，展开/收起用高度或 `grid-template-rows` 过渡（不要在动画中触发整页布局抖动）。
- **必须兼容原生校验**：折叠区块里有 `required` 字段，提交时若校验失败，浏览器无法聚焦隐藏字段。要求：监听 `invalid` 事件（捕获阶段），自动展开含无效字段的区块并聚焦第一个无效字段，同时滚动到可视区；不得关闭原生校验、不得改成自定义校验。
- 折叠按钮是原生 `<button>`，带 `aria-expanded` 与 `aria-controls`；折叠内容用 `hidden`/`inert` 之一保证不可聚焦（展开后恢复）。状态徽标随字段内容更新（有值即"已填写"，纯展示）。
- 01 区块（题目、分区、语言、代码）始终展开。

## F4. 底部固定保存条与整体验收
- 手机：底部 sticky 操作条（渐变遮罩 + 主按钮「保存这条记录」），不遮挡输入框和键盘弹出时的内容；桌面保持普通位置的主按钮即可。
- 保存成功/失败提示沿用现有机制，不改文案逻辑。
- 补充静态资源测试：断言新增的卡片/折叠按钮有 `aria-expanded`/`aria-controls`、`invalid` 展开逻辑存在、文件 input 仍是原生 `type="file"` 且未被 `display:none`、`backdrop-filter` 规则位置合规。

## 不要做
不动后端/数据库/支付/AI；不新增依赖；不改既有测试（确需调整的单条断言须在说明中逐条列出原因）；不在项目目录创建临时/缓存目录；不改其他页面的版式（套餐、小组、讨论区等留到后续轮次，但新增的卡片/徽标/拖放等样式请抽成可复用类名，方便以后复用）。

## 验收（Claude 会逐条核对）
1. 手机 390×800 与桌面 1280×800，两个主题：截图中各区块是明显分层的卡片，有编号、标题、一句话说明；无原生文件框外观；无横向溢出（另测 1024/800/360/320）。
2. 上传：点击选择、键盘选择、桌面拖放三种方式都能触发预览与"识别"按钮可用；移除图片恢复初始；AI 忙碌/额度用完时的禁用状态不变。
3. 折叠：02/03 默认折叠；点击展开/收起顺滑；**在 03 里留空必填字段直接点保存，会自动展开并聚焦该字段**（给出验证记录）。

5. `prefers-reduced-motion` 下无动画；帧率不退化（有界面浏览器下滚动与展开过程无明显掉帧，给出数据即可）。
6. 全量 `pytest -q` 通过（云端缺支付 SDK/中文字体除外）；说明里列出改动文件、新增/调整的测试、截图（两主题 × 手机/桌面 × 折叠/展开）。
