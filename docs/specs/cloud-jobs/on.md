# 任务 ON（分支 `cs/on`）


## 0. 目标与依据
对标笔记：Excalidraw 这类“打开就能用”的产品不让你先配置；很多开源产品用**首次清单**带新手走完第一轮。我们的现状：注册成功后只有一句“去新增记录”；没有示例数据；空状态大多只有说明文字。目标：新用户第一次进入就知道“下一步做什么”，并且能**一键载入几条示例错题**先体验一遍，随时一键清掉。**不改后端、不加迁移**（示例记录用现有接口创建，靠标题前缀 `【示例】` 识别）。

## 1. 你负责的文件
新增 `static/onboarding.js` / `static/onboarding.css`（`window.Onboarding`）、`static/index.html` 里引入它们的标签、`static/app.js` 里**最小接线**（`loadHome()` 渲染完总览后分发一次 `app:home-rendered` 自定义事件；`enterApp()` / `signedOut()` 里调用 `Onboarding.reset()`；各空状态按钮的跳转复用现有 `showView`）、测试。**不要碰** `overview.js` / `overview.css`（OV 任务在改）——清单卡片由 `onboarding.js` 在收到 `app:home-rendered` 后把自己插入 `#home` 的最上方（`#onboarding-card`），不存在则创建。**不要碰**后端、论坛、套餐、复习页内部逻辑。

## 2. 清单卡片（总览最上方）
- 三步，状态**从数据推导**，不自己存“完成”标记：① **记下第一条错题**（总览数据 / `GET /api/mistakes` 有任意记录）；② **完成第一次复习**（用户有任意复习记录：可用 `GET /api/overview` 已有字段或活动统计；若现有接口拿不到，就用 `GET /api/mistakes?due_only=false` 里任一条 `last_reviewed_at` 非空判断）；③ **看一眼薄弱点分析**（前端在用户进入“薄弱点分析”页时写 `localStorage` 键 `onboarding-weakness-seen:<用户id>`，try/catch；取不到时按未完成）。
- 展示：标题“开始之前 · 3 步走完第一轮”、进度环（`n / 3`）、三行步骤（已完成打勾并划线，未完成的第一项高亮并带“去做”按钮：①→新增记录页，②→今日复习，③→薄弱点分析）。全部完成后卡片显示一次“第一轮完成”祝贺并自动收起；用户可点“不再显示”（`localStorage` 键 `onboarding-dismissed:<用户id>`）。已有 ≥10 条记录或已完成三步的老用户**不显示**。体验账号显示清单但第③步以外的“去做”照常可用。
- **一键载入示例数据**：仅当用户**一条记录都没有**时，卡片里显示按钮“载入 4 条示例错题体验一下”。点击后依次用现有的新增记录接口（读 `app.js` 里新增记录提交的请求格式与字段，别猜）创建 4 条示例（标题均以 `【示例】` 开头，分区覆盖 算法 / 数据库 / 高等数学 / 概率统计，各带真实合理的思路、一段简短代码（高数 / 概率可无代码）和易错原因，内容别写成“示例示例”，要像真实错题）。创建过程中按钮禁用并显示进度“正在载入 2 / 4”；任一条失败：已创建的保留，显示失败原因和“重试剩下的”。完成后刷新总览与侧栏数字，并提示“已载入示例，可以去今日复习试试；不需要时点‘清除示例’”。
- **清除示例**：当存在任何标题以 `【示例】` 开头的记录时，卡片（或“全部记录”页头）显示“清除示例数据”按钮；点击后在卡片里内联出现二次确认（不要用 `confirm()`）：“将删除 N 条以【示例】开头的记录，你自己的记录不受影响”，确认后用现有的删除记录接口逐条删除，进度与失败处理同上，完成后刷新。
- 示例记录会进入真实统计（打卡 / 热力图等），在说明文字里讲清楚“示例记录也会计入统计，清除后一并消失”。

## 3. 空状态的“下一步”按钮
给这些空状态补**可点击的下一步**（沿用现有印章空状态的样式；只改文案与按钮，不改布局逻辑）：今日复习为空（有记录但今天没有到期 → “今天没有要复习的，去看看薄弱点” / 没有任何记录 → “去新增第一条错题”+ 载入示例）、全部记录为空（“新增记录” / “载入示例”）、薄弱点分析不足（说明还差几条、“去新增记录”）、错因专题不足、掌握度趋势无数据。各按钮的跳转用现有 `showView(...)`；不要新增路由。

## 4. 测试
Node 行为测试：清单步骤推导（各组合）、显示 / 隐藏规则（老用户、已完成、已关闭、体验账号）、示例载入的串行流程（全部成功 / 中途失败 / 重试剩下的 / 迟到响应 / 重复点击只发一次）、清除示例（只删 `【示例】` 前缀、确认流程、部分失败）、`app:home-rendered` 接线与 `reset()`（登出再登录别的账号不残留）、`localStorage` 抛异常时不崩；静态契约（版本号、无十六进制 / `!important` / 内联样式）；对比度。变异检查挑 2–3 处（只删前缀匹配的记录、步骤②的判断、老用户不显示）。
