# 需求：产品介绍落地页 + 独立登录/注册页 + 双主题（水墨 / 栖间）

给 Codex 的实现需求。Claude 负责审查和验收，请按下面的范围和验收标准做，不要扩大范围。
适用约定见仓库根目录 `AGENTS.md`（尤其：测试临时目录不可写时先停下来报告，不要在项目目录里建临时目录）。

## 1. 目标（用户原话要点）
1. 现在的登录页做成**产品介绍页**，轮播几张**风景图**。
2. 用户准备登录/注册时，再进入**专门的登录注册页面**；登录注册不要出现在主页面上。
3. 登录注册页里**多余的提示尽量去掉**，更有美感。
4. 登录后才是现有的项目首页（学习大厅）。
5. 现有的「水墨红笔」和新的「栖间」（清新自然、毛玻璃面板、可换风景背景）**两种风格都保留，用户自己选**。
6. 避免元素挤成一排。（子页面顶部 9 个按钮一排的问题已经在 `4fb01ab`/`5629fe2` 修了：只留返回 + 切换页面菜单 + 刷新。请你检查其他页面是否还有类似"一排挤满"的地方，如各页的 `.actions` 按钮行，窄屏下改成合理换行或分组。）

## 2. 现状（已核实）
- `static/index.html`：`<header class="header">`、`#intro`（产品介绍区，第 76 行起）、`#auth.auth-grid`（登录 `#login-form`、注册 `#register-form`、`#forgot-form`、`#reset-form` 等，第 162 行起）、`#app`（登录后）。
- `static/app.js`：`$("#auth").hidden` 在 362 行（登出/未登录）和 702 行（登录后）切换；登录 2302、注册 2316、体验账号 2327、忘记密码 2353、重置密码 2368。
- `static/intro.js` / `intro.css`：首屏开场与介绍区；`static/cursor-fx.js`：全站山水涟漪背景（手机端静态图+轻微涟漪，已定）。
- 样式令牌在 `static/style.css` 顶部 `:root`。
- 受测试约束：`tests/test_cursor_fx_assets.py`、`test_layout_assets.py`、`test_seal_assets.py`、`test_dashboard.py`。尤其：`backdrop-filter` 只能出现在 `@media (hover: hover) and (pointer: fine)` 内；任何 `color-mix(... transparent)` 的半透明背景必须有不透明的 `@supports` 回退。**不要为了过测试而改测试，先满足规则。**

## 3. 范围

### 3.1 三个视图与路由
- `welcome`（未登录默认）：产品介绍 + 风景轮播 + 一个主按钮「开始使用」（进入 `auth`）和一个次级「免注册体验」。
- `auth`：全屏独立页，只放登录/注册，两者用**切换**而不是并排两个卡片；「忘记密码」「重置」保持现有功能。只留必要文案：去掉 `eyebrow` 小标签、「使用用户名登录，不是邮箱」这类提示（出错时才显示）、体验账号的长说明（放到「免注册体验」按钮的 `title`/辅助文字里一句话即可）。
- `app`：登录后，保持现状。
- 用 hash 路由（`#/welcome`、`#/auth`）让浏览器后退有效；已登录访问 `#/auth` 直接进 `app`。不改后端接口。
- 所有现有元素 id（`login-form`、`register-form`、`forgot-form`、`reset-form`、`auth` 等）和 `aria-label` 尽量保留；确需改动的同步更新测试，并在最终说明里列出。

### 3.2 产品介绍页内容
- 保留现有 `#intro` 的核心文案（让做错的题，成为下次的把握；错因→到期复习→换题验证三步），精简，不堆卡片。
- 风景轮播：3–4 张场景，自动轮播（约 8–10 秒淡入淡出）、可手动切换（圆点或左右键）、`prefers-reduced-motion` 下不自动播。
- **素材来源（需要 Claude/用户确认的决定，默认按此做）**：云端和本机都没有现成的授权图片，所以第一版用**纯 SVG/CSS 绘制的场景**（雪山夜窗、雾湖森林、雨夜书房/暖灯，加上现有水墨山水），存放在 `static/scenes/`，通过**一个配置数组**（`id`、`name`、`src` 或内联 SVG、`accent` 色）驱动。以后换成真实照片只改这个数组。不要从网上下载版权不明的图。
- 手机端：静态首图 + 轻微涟漪（沿用 cursor-fx 现有规则），不自动轮播，滑动或点圆点才切换，避免耗电和卡顿。

### 3.3 双主题（用户可选）
- 两套：`ink`（水墨红笔，现状）和 `qixi`（栖间：清新自然、毛玻璃面板、随场景换背景和强调色）。
- 通过 `<html data-theme="ink|qixi">` 切换，所有颜色/圆角走 CSS 变量，**不要复制两份样式**。
- 选择入口：落地页右上角和登录后头像菜单（`account-menu-panel`）里各放一个；选择存 `localStorage`（try/catch 包裹，读不到就用默认 `ink`）。
- 栖间主题的版式方向：左侧大标题 + 一句话，右侧一块面板；顶部只留极少导航；多留白。毛玻璃面板只在 `(hover:hover) and (pointer:fine)` 下启用模糊，其余用不透明/半透明纯色回退。
- 切换主题不能刷新页面，不能破坏现有的一次性开场动画和盖章动效。

### 3.4 不要做
- 不动后端、数据库、支付、AI 相关代码。
- 不新增依赖，不引入构建步骤（项目是纯静态 JS）。
- 不改 `README` 之外的文档；不创建任何临时/缓存目录在项目目录里。

## 4. 验收标准（Claude 会逐条核对）
1. 未登录打开站点：只看到介绍页和轮播，没有任何登录表单；点「开始使用」进入独立登录/注册页；后退回到介绍页。
2. 登录/注册页上没有 `eyebrow` 小标签和多余说明；登录、注册、体验账号、忘记/重置密码**功能完全保留**，测试能跑通。
3. 登录成功进入学习大厅；刷新页面仍保持登录且不闪回介绍页。
4. 两个主题都能切换并记忆；任一主题下 1280/1024/800/390/360/320 宽度无横向溢出，文字不溢出按钮。
5. 轮播：自动、手动、减少动效、手机静态四种行为都正确；切换时没有明显卡顿。
6. `pytest -q` 全量通过（云端环境缺支付 SDK/中文字体时，仅这些已知环境原因的失败可忽略，需在说明里写明）；新增的静态资源测试覆盖：hash 路由元素存在、主题令牌成对、`backdrop-filter` 规则、轮播配置数组非空。
7. 最终说明里列出：改了哪些文件、改了哪些 id/测试及原因、做了哪些真实浏览器检查（桌面+手机截图）。

## 5. 建议拆分（降低风险，每步单独可验证）
- A. 路由与视图拆分（welcome / auth / app），不改视觉。
- B. 登录注册页精简与美化，切换式表单。
- C. 介绍页 + 场景轮播（含手机降级）。
- D. 双主题令牌与切换入口。
