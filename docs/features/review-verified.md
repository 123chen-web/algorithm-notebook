# 做题验证复习

> 自评容易偏高，而排期算法（FSRS）完全相信给它的成绩。所以复习成绩尽量由**做题结果**决定，而不是自己打分。

## 四种复习方式（只对算法分区）

| 方式 | 做什么 | 成绩怎么来 |
| --- | --- | --- |
| 去原题限时重做 | 在新标签页打开原题，从空白开始，计时 | 做完点结果，成绩由结果算出 |
| 做一道类似题 | 从同一套路里挑一道带链接、你没做过的题（“举一反三”接口），计时 | 同上；做不出来默认顺手记进错题本 |
| 默写关键代码 | 凭记忆写出正确代码，逐行对照 | 按逐行相似度算 |
| 只回忆（自评） | 先回忆再显示错因，自己打分 | 自己打，但有上限（见下） |

复习方式放在“显示错因”**之前**：重做和类似题要先动手，不能先看到答案。

## 成绩规则

服务端是唯一的算分处（`review_verify.py`），前端 `redo-flow.js` 里的同名函数只为了预先显示，
两边共用 `tests/fixtures/verified_grading.json` 这张对照表，规则不会悄悄分叉。

做完了吗？四个结果：

| 结果 | 重做原题 | 类似题 |
| --- | --- | --- |
| 一次通过，没看提示 | 用时不超过时限的 1/3 → 很熟（5）；否则记得（4） | 记得（4） |
| 改了几次才通过 | 记得（4） | 记得（4） |
| 看了提示才做出来 | 很吃力（3） | 很吃力（3） |
| 没做出来，或看了题解 | 答错了（0） | 答错了（0） |

- 超过时限才通过，最高算很吃力（3）。
- 只有“原题重做、一次通过、用时不超过 1/3”能拿到“很熟”。类似题和默写最高是“记得”。
- 默写：相似度 ≥ 0.85 记得，≥ 0.6 很吃力，否则答错。
- 前端上报时带 `evidence.auto = true`，服务端重算并覆盖前端传来的 `quality`，并把 `suggested`、`final` 写进 `evidence`。

## 自评的限制（只对算法分区）

数学等其他分区没有做题验证的办法，自评是唯一的评分方式，所以不受下面的限制。

1. 自评最高算“记得”（4），不能给“很熟”（5）。被压低时原分记在 `evidence.suggested`，可以看出自评是否虚高。
2. **连续两次**都是自评，下一次间隔最多 14 天（只限制间隔和到期日，稳定度照常记录）。中间做过一次验证，限制就解除。
   触发时评分响应多一个 `unverified_cap: true`，前端提示一句。
3. 上一次只是自评时，复习页默认改用做题验证，并提示这条规则。
4. 预览接口 `GET /api/mistakes/{id}/preview?mode=` 与真正评分一致（默认 `recall`）。

## 接口与数据

- `POST /api/mistakes/{id}/review`：`mode` 增加 `similar`；`evidence` 新增字段
  `result`（`clean`/`retry`/`hinted`/`failed`）、`limit_seconds`、`auto`（只能是 true）、`ref`（类似题题名，≤60 字）。
  `auto` 为 true 的 `recall` 请求返回 422。
- 复习队列 `GET /api/review/queue` 的每条多一个 `last_review_mode`，专注模式据此提示“上次只是自评”。
- 没有新的数据库迁移：`reviews.mode` 本来就是文本。

## 还没做

- 扩展自动读取判题结果（Accepted / Wrong Answer）来代替点“做完了吗”：上一批的结果页录入还没在真实网站上试过，先不依赖它。
- 队列按套路穿插排序（交错练习），目前仍按逾期程度排序。
- 旧用户的历史复习记录 `mode` 全是 `recall`，所以升级后他们的第一次自评就可能被两周上限压住；做一次验证即可解除。
