# 账号与隐私运维说明

本说明对应账号安全与隐私功能、数据库迁移版本 4，以及版本日期为 `2026-10-03` 的服务条款和隐私政策。产品名只在 `legal.py` 的 `PRODUCT_NAME` 常量中定义；条款版本由同文件的 `TERMS_VERSION` 定义。

## 账号功能

所有账号写接口沿用站内会话 Cookie 和 `X-CSRF-Protection: 1` 安全校验，请通过同源前端使用。

| 功能 | 接口与请求体 | 成功后的行为 |
| --- | --- | --- |
| 修改密码 | `POST /api/me/password`：`{current_password, new_password}` | 返回 `{ok: true, revoked_sessions: n}`；轮换当前设备会话 Cookie，旧令牌立即失效，退出其他设备，清除已有找回密码令牌 |
| 退出其他设备 | `POST /api/me/sessions/revoke-others`：`{}` | 返回 `{ok: true, revoked: n}`；仅保留当前会话，体验账号也可使用 |
| 注销账号 | `POST /api/me/delete-account`：`{password}` | 返回 `{ok: true}`，库内撤销全部会话；响应不下发删除 Cookie，避免迟到响应清掉新登录账号的 Cookie；按下表删除或脱敏数据 |
| 修改邮箱 | `PUT /api/me/email`：`{email, password}` | 验证当前密码后更新邮箱，同一事务删除全部未使用的找回密码令牌；失败时令牌不变 |
| 注册 | `POST /api/auth/register`：原字段加 `accept_terms: true` | 写入条款同意时间与版本；未同意时返回“请先阅读并同意服务条款和隐私政策” |
| 导出学习数据 | `GET /api/export` | 返回现有 JSON 导出；建议注销前自行保存 |

当前密码错误使用 HTTP 400，文案为“当前密码不正确”，避免前端把密码错误当成会话过期。改密码、注销、修改邮箱共享当前密码验证限流：按用户累计 15 分钟内最多 5 次失败，验证成功清零该用户失败计数；按 IP 累计 15 分钟内最多 20 次尝试。检查均在 PBKDF2 密码计算之前，超限返回 HTTP 429：“尝试次数过多，请 15 分钟后再试”。限流沿用进程内实现，多进程部署并不共享计数。

退出其他设备、改密码、注销在取得数据库写锁后，复查请求会话仍存在且属于当前用户，已撤销的在途请求返回 401。前端在这些认证变更请求未决期间锁住登出、切换账号和关闭对话框；完成后释放锁。绑定邮箱表单在登出、切换账号时清空（含密码），提交响应只更新发起请求的账号，迟到响应不能覆盖新账号状态。

体验账号不能改密码，也不能自助注销；注销提示“体验账号到期会自动清理”。管理员不能自助注销，应先通过 `admin_tool.py` 撤销管理员身份。小组创建者如仍有其他成员，注销返回 HTTP 409，并点名需要先处理的小组；失败时不会删掉账号数据。只剩创建者本人的小组随注销删除。

## 注销时的数据处理

注销采用单个数据库写事务，先检查密码和小组约束，再修改数据；数据库中途失败会整体回滚。头像文件在数据库事务提交后删除，文件不存在时不报错；删除失败只记日志，注销仍成功，已注销账号头像始终返回 404。

| 数据 | 处理方式 |
| --- | --- |
| `sessions`、`password_resets` | 删除该用户全部会话和找回密码令牌 |
| `problems` 及其易错点、复习记录、变体、标签关系 | 删除题目，通过外键级联删除个人学习数据 |
| `weakness_insights`、`mistake_clusters`、`ai_usage` | 删除该用户的数据 |
| `import_previews` | 删除该用户的私有文件预览和导入确认结果；预览有效 30 分钟，过期内容在下一次成功预览时清理 |
| `avatar_reports` | 删除该用户作为举报人或头像主人的记录 |
| `ai_calls` | 将 `user_id` 置为 NULL，保留无账号关联的调用成本元数据 |
| `study_group_members` | 退出所有小组；用户创建且只剩自己的小组也删除 |
| `posts`、`post_comments`、`reports` | 保留内容，通过作者关联显示占位用户名 |
| `orders` | 保留财务记录，继续关联脱敏后的用户行 |
| 头像文件 | 删除 `data/avatars/{id}.jpg`，事务提交后执行 |
| `users` | 保留脱敏占位行，具体字段见下文；套餐字段保留原值 |

脱敏用户的 `username` 为 `已注销用户 #<id>`；如该名字已被存量账号占用，从 `已注销用户 #<id>-2` 起选第一个空闲后缀。`email`、`last_reminder_sent` 置 NULL，`avatar_version`、`is_admin` 置 0，`deleted_at` 写入当前 UTC 时间；`password_hash` 替换为格式合法、不会匹配真实密码的占位值。删除个人学习记录不会删除订单或论坛内容。占位哈希不能用于恢复登录。

个人主页只供登录用户查看，展示现有用户名、头像、自己填写的公开简介，以及当前仍保留的题目数、累计录入题目数、易错点数、复习次数、连续天数和徽章数；不展示邮箱、代码、思路、错因或单条复习记录。简介最多 200 字，可自行清空；注销账号会清空 `users.bio` 和 `users.lifetime_problem_count`。不参与公开榜单只影响榜单，主页仍能从讨论作者或小组成员入口查看；被封禁、已注销账号的主页返回 404。当前题目、错因及复习数随删除学习记录减少；累计录入以功能启用时现有题目为基线，此后实际插入计数，删除不减少，回滚和重复导入不计数。升级前已经删除的题目无法重建历史累计。

下单与每个导入文件的写事务均复查账号未注销。已注销账号不能新增订单或导入学习记录。有效财务回调继续写订单状态、交易号和付款时间，退款也继续更新财务记录；若账号已注销，只跳过该用户套餐权益变更并记日志，保留脱敏行原有套餐字段。

登录和认证会排除 `deleted_at IS NOT NULL` 的账号。排行榜、小组成员、后台用户总数等统计、提醒与体验账号清理排除已注销用户；论坛作者展示继续读取脱敏用户名。现有管理后台通过 `/api/admin/dashboard` 提供聚合统计，没有独立的用户列表接口；`/api/admin/reports` 保留论坛举报及其脱敏作者显示。管理后台的用户总数不包含已注销用户，财务和成本记录仍按各自现有统计规则保留。

服务器历史备份不会立即重写。`backup.py` 默认 `BACKUP_KEEP=14`，保留最近约 14 份并滚动覆盖；实际旧数据清除时间取决于备份频率和配置。运维应核对配置，避免承诺固定天数或把 `--keep 0`（全部保留）误当成滚动清理，并在变更策略时同步隐私政策。

## 密码策略

注册、重置密码和修改密码都会检查新设置的密码：

- 长度为 8–128 个字符。
- 拒绝内置常见弱口令表中的密码，例如 `12345678`、`password123`、`qwerty123`、`admin123`，比较不区分大小写；纯重复字符也拒绝。
- 不能等于用户名或邮箱 `@` 前的部分，比较不区分大小写。
- 修改密码时新密码不能与当前密码相同。

失败文案区分“密码至少 8 位”“这个密码太常见，请换一个”“密码不能和用户名或邮箱相同”。这套规则只在设置新密码时使用；登录仍兼容历史 6–7 位密码，升级不会强制所有老用户重设密码。存储值缺少分隔符或包含非十六进制内容时，密码校验返回 False，而不会让接口抛出格式异常。

重置密码的 HTTP 400 含机器可读 `code`：有效链接配弱密码为 `weak_password`，前端保留链接并显示密码提示；链接无效或过期为 `invalid_token`，前端清除链接并提示重新收邮件。

## 用户名规范与保留名

新注册和改名先拒绝 Unicode `Cc`、`Cf` 类别的控制或格式字符（含零宽、方向控制字符），返回 HTTP 400：“用户名不能包含不可见字符”；再按 `unicodedata.normalize("NFKC", value).strip().lower()` 规范化，非空且不超过 32 个字符。例如全角字母会转换为半角，存库为规范化的小写用户名。保留名使用同一规范化比较。登录优先匹配库中精确存在的输入名字，未找到再规范化匹配，既有全角或含不可见字符账号仍可用其原名字登录。

注册和改名禁止以下规范化后精确匹配的名称：

`admin`、`administrator`、`root`、`system`、`support`、`official`、`moderator`、`staff`、`官方`、`管理员`、`客服`、`系统`、`站长`、`版主`、`欧叶`、`欧叶oy`、`算法错题本`。

任何以 `已注销用户` 开头的名字也被保留。冲突返回 HTTP 400：“这个用户名已被保留”。历史已有账号不会因名称被保留而失去登录能力。

`ADMIN_USERNAME` 不提供公开注册或启动授予管理员的例外。管理员身份与用户名独立，管理员改名后身份不变；固定保留名和注销占位前缀继续保护。其他 Unicode 同形字（如西里尔字母）不在本轮处理范围。

## 管理员模型与命令行工具

管理员身份由数据库 `users.is_admin` 决定，不再靠用户名实时推导，因此管理员改名后仍保有权限。已注销账号不参加“是否已有管理员”的判断。

公开注册永远创建普通用户，应用启动不按名字补权。当前已发布的迁移 4 只添加账号字段，没有 `ADMIN_USERNAME` 一次性回填逻辑；本轮保持旧迁移原样，不新增迁移。数据库里已有的 `is_admin=1`（无论此前如何授予）保持不变。`ADMIN_USERNAME` 继续作为保留名配置，不授予权限。之后仅通过 `admin_tool.py` 明确授予或撤销身份。样本世界先注册普通样本账号，再在隔离样本数据库中按用户 ID 用 SQL 授予样本管理员。

可以维护多名管理员，权限取决于各用户行的字段。工具只依赖数据库模块和标准库，不打印密码哈希等敏感字段。

在配置与应用相同数据库路径的环境中运行：

```powershell
python -B admin_tool.py list
python -B admin_tool.py check-usernames
python -B admin_tool.py grant 学习助手
python -B admin_tool.py grant --id 42
python -B admin_tool.py revoke 学习助手
python -B admin_tool.py revoke --id 42
python -B admin_tool.py revoke 学习助手 --force
```

`list` 列出有效管理员；`grant` 给已有有效账号授予管理员身份；`revoke` 撤销指定账号身份。必须输入库中的精确用户名或使用 `--id`。名字的规范化匹配有多个候选时，即使输入精确名字，工具也拒绝执行并列出候选 ID，请用 `--id` 明确指定。没有 `--force` 时不能撤销最后一个管理员。强制撤销后应用重启不会自动恢复其管理员身份。交接身份时先授予新账号，再撤销原账号。

`check-usernames` 以 SQLite `mode=ro` 只读打开已有库，不创建库、不执行 `init_db()` 或迁移、不修改用户。它列出有效存量账号的规范化冲突、不可见字符和保留注销前缀占用；正常注销生成的占位行不列为冲突。建议升级前检查，出现歧义先由运维确认真实账号，再按 ID 管理身份。

## 条款、隐私政策与注册同意

`GET /terms`、`GET /privacy` 是无需登录的完整 HTML 页面。使用现有主题样式和新建的 `static/legal.css`，没有内联脚本或样式，沿用中间件的 CSP 与其他安全头；响应使用 `Cache-Control: public, max-age=300`，可以缓存 5 分钟，不能配置永久缓存。页面沿用浏览器本地保存的界面风格，并按浏览器的深色偏好使用现有深色背景与文字令牌。

| 环境变量 | 用途 | 未配置或为空时 |
| --- | --- | --- |
| `LEGAL_OPERATOR_NAME` | 条款与隐私政策上的运营者名称 | 显示“本站管理员” |
| `LEGAL_CONTACT_EMAIL` | 两页上的联系邮箱 | 显示“请通过站内渠道联系管理员” |

运营者名称和联系邮箱通过 `html.escape` 转义后作为文本插入，不作为 HTML 或脚本执行。上线前应填写真实、有效的信息；不需要为这两个页面配置新的第三方服务。

注册请求需要 `accept_terms: true`。为便于前端直接显示中文，缺失字段按未同意处理，与 false 一样返回 HTTP 400：“请先阅读并同意服务条款和隐私政策”。成功后将 UTC ISO 格式时间写入 `terms_accepted_at`，并把 `TERMS_VERSION` 写入 `terms_version`。体验账号接口不要求同意字段，也不写入条款同意记录。

内容更新时应同时更新版本日期和站内提示。新版本不会自动给老用户补造同意记录；如变化需要重新征得同意，应补充相应产品流程后再启用新的数据处理。

## 已有部署的升级

1. 按现有备份与恢复流程先备份并校验数据库及头像；确认迁移版本与程序版本一致。
2. 启动新版本时 `init_db()` 自动执行迁移 4，新增 `deleted_at`、`is_admin`、`terms_accepted_at`、`terms_version`；迁移由既有迁移机制管理事务和版本号，不手工改 `user_version`。
3. 老用户 `deleted_at` 为 NULL、`is_admin` 默认 0，学习与套餐数据不变；老用户 `terms_accepted_at` 和 `terms_version` 为 NULL，表示未记录这次注册同意，不能解释为历史已经同意。
4. 迁移或重启不会按 `ADMIN_USERNAME` 自动授予身份，现有 `is_admin` 保持不变。用 `admin_tool.py list` 和 `check-usernames` 核对；没有管理员的旧站点需要运维确认正确用户 ID，再用 `admin_tool.py grant --id <ID>` 显式授权。不要依赖注册指定名字取得管理权限。
5. 核对两页的运营者与联系信息、AI 和 SMTP 服务商、备份保留配置；在使用前端账号功能前，确保前后端接口版本配套。

迁移列表必须严格递增。本轮 SEC 不新增迁移，也不改已发布的迁移 4；实际最新版本以 `db.py` 为准，不要把已升级数据库交给只支持旧版本的程序。被封禁用户仍不能自助注销，遵循封禁即时生效。

## 上线前请法律人士审阅这两页

这两页是产品与运维说明草稿，发布前需要结合运营者身份、部署地区、服务商、付费规则和实际数据处理安排审阅。尤其需要确认：

- 跨境传输：AI 与 SMTP 服务商所在地、实际接收的数据、处理协议，以及是否需要额外告知、同意或其他手续。
- 个人信息保护法的告知义务：运营者主体信息、处理目的与方式、个人信息类别、权利行使渠道，以及第三方服务商和变化告知是否充分。
- 未成年人：适用年龄、监护人同意与核验方式，以及对未成年人个人信息的额外要求。
- AI 生成内容标识：页面、生成练习题与导出内容中的标识安排是否满足适用规则。
- 争议解决条款：目前“以运营者所在地法律为准”为占位表述，需根据所在地和用户范围确定适用法律、管辖与争议处理方式；同时审阅责任限制和付费退款规则。
- 数据保存期限：订单与财务记录应保留多久、论坛和举报保留的必要性、AI 成本元数据的期限、备份频率与约 14 份滚动保留是否合适，以及恢复备份后如何避免重新暴露已注销数据。

运维应把审阅结果与实际配置、前端提示和数据库行为保持一致，再开放相应功能。
