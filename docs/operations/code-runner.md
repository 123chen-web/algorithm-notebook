# 可选的独立代码运行服务

欧叶 OY 不在 Web 进程执行用户代码。复习详情的运行面板通过服务端适配器向
**站长自己管理的独立 Judge0 兼容沙箱**提交当前代码与标准输入。
默认支持 Python 和 C++；不会向公开演示服务发送代码，不安装或启动沙箱。
现有依赖清单不变，也没有给网站容器挂载 Docker socket。

站长将来准备好独立服务后，再配置 `CODE_RUNNER_URL`、`CODE_RUNNER_TOKEN`；
当前交付只改示例配置，未修改实际 `.env`，未部署服务器。未配置时面板给出提示，
接口返回 503。远程服务必须 HTTPS，本机 loopback 可 HTTP，不跟随重定向或代理。
token 只进入请求头，不进入 URL、浏览器或日志。

服务必须更新到修复安全漏洞的版本，使用自身的沙箱、隔离用户、资源限制，
不能访问网站数据目录、密钥、宿主机管理接口或其他网络。适配器提出以下固定限制，
站长须确认运行服务实际执行这些限制，不能仅凭客户端请求认定隔离有效：

- CPU 2 秒、墙钟 5 秒、内存 128000 KB、文件 64 KB、最多 16 进程/线程；
- 禁止网络；不接受客户端传来的编译选项、命令行、附加文件、回调地址；
- 仅单文件 Python（语言 ID 71）、C++（ID 54），须核对自建实例语言列表；
- 当前草稿最多 40000 字符，标准输入 10000 字符；响应 64 KiB 上限；
  标准输出/错误/编译信息各最多展示 8000 字符，超出会标明截断。

协议按 [Judge0 官方 API 文档](https://ce.judge0.com/) 实现：提交时 Base64 编码，
使用 `wait=false`，服务端有界查询结果。每个 Web 进程最多 2 个同时查询的运行请求，
每用户每进程每分钟最多 6 次；多进程部署还须由独立运行服务或网关设置全局任务上限。
查询等待超时不代表沙箱任务已取消；沙箱必须执行自身的时间限制和记录保留规则。
运行服务可能保留源代码，站长须配置清理与访问控制，运行面板会明确告知数据去向。

`POST /api/mistakes/{id}/run` 只接受普通账号自己的题目、全局 CSRF 头和固定输入字段。
运行只展示标准输出和编译/运行错误，**不判定答案是否正确**，不改变代码、复习调度或
每日 AI 额度。用户可以改运行面板里的草稿，这份临时草稿不自动保存到笔记。

本机测试只使用假的运行服务响应，并验证权限、固定限制、错误降级、响应上限、
Unicode、输出截断和会话守卫。没有真实安装或调用沙箱；正式服务的隔离强度、
编译器版本、排队容量与实际运行还需站长接好服务后独立验收。
