# 微信提醒：申请 SendKey / PushPlus token

每日「今日复习」提醒除了邮件（见 [mail.md](mail.md)），还可以通过 **Server酱** 或 **PushPlus** 推送到微信。用户在账号菜单的「微信提醒」卡片里自行配置，运维不需要为每个用户做任何事。

## 渠道怎么选

| 渠道 | 适用 | 申请地址 |
| --- | --- | --- |
| Server酱 | 个人使用，配置最简单 | <https://sct.ftqq.com/> |
| PushPlus | 个人使用，备选渠道 | <https://www.pushplus.plus/> |

两个渠道都免费、都只需微信扫码登录，不需要自己的公众号。

## Server酱：申请 SendKey

1. 打开 <https://sctapi.ftqq.com/>（sct.ftqq.com），用微信扫码登录。
2. 登录后在「Key & API」页面复制 **SendKey**，形如 `SCT` 开头的一串字母数字（8–64 位）。
3. 回到本站：右上角头像 → 账号菜单 → 「微信提醒」：
   - 渠道选 **Server酱（微信推送）**；
   - 把 SendKey 粘贴进 **SendKey / token** 输入框；
   - 勾选「开启微信提醒」，点「保存」；
   - 点「发送测试消息」，手机微信上收到「欧叶OY：微信提醒测试」即为成功。
4. 同一页面可以随时更换 Key 或关闭微信提醒；关闭后提醒仍会按原逻辑发邮件。

## PushPlus：申请 token

1. 打开 <https://www.pushplus.plus/>，用微信扫码登录。
2. 在「一对一推送」页面复制你的 **token**（32 位小写十六进制字符串）。
3. 本站账号菜单 → 「微信提醒」：
   - 渠道选 **PushPlus（微信推送）**；
   - 粘贴 token，勾选「开启微信提醒」，保存后点「发送测试消息」确认。
4. PushPlus 默认推送给登录账号本人的微信，无需关注额外公众号以外的配置；若页面提示需要关注公众号，按 PushPlus 官网引导关注「pushplus 推送加」即可。

## 安全与隐私

- SendKey/token **只保存在服务器数据库里**，任何接口都不会返回原文：设置页只显示**尾号 4 位**，输入框始终留空（留空保存表示不修改原密钥）。
- 应用日志、每日提醒脚本的输出里只记录渠道和失败分类（网络 / 认证 / 限流 / 服务商），**不打印密钥**。
- 推送地址在代码里固定（`push_channels.py`），不跟随跳转，用户无法指定发送 URL。
- 注销账号时，推送配置随账号数据一并删除。

## 发送规则与自动关闭

- 每日提醒脚本 `send_reminders.py` 的选人、按用户时区算当地日期、同一天去重逻辑与邮件完全一致；启用了微信渠道的用户走推送，其余用户继续走邮件。没有邮箱但配置了微信的用户也能收到提醒。
- 推送**连续失败 5 次**（认证失败、服务商故障等）后，系统会自动把该用户的微信提醒开关关闭，设置页提示「已自动关闭，请检查 Key」。用户修正 Key 后重新保存即可（重新提交密钥会清零失败计数）。
- 推送失败的当天不会标记为「已发送」，下次运行脚本会继续补发。
- 「发送测试消息」按钮每人每小时最多 5 次，超限会提示稍后再试；测试消息不计入自动关闭的失败次数。

## 故障排查（用户看到的提示含义）

| 测试结果提示 | 含义与处理 |
| --- | --- |
| 测试消息已发送，请在微信里确认收到 | 配置正确；若微信没收到，检查服务商公众号的消息免打扰 / 折叠。 |
| 无法连接推送服务商（网络） | 服务器到服务商的网络不通或超时，检查服务器出站网络与 DNS。 |
| 服务商拒绝了密钥（认证失败） | Key/token 填错、被重置或渠道选错；到服务商官网重新复制后保存。 |
| 推送被服务商限流 | 触发了服务商的频控，稍后再试或换一个渠道。 |
| 推送服务商暂时不可用 | 服务商返回了非预期结果或 5xx，稍后重试。 |

服务端排查时可直接用 `push_channels.send(channel, key, title, body)` 配合假的 HTTP 客户端做分类验证；真实的服务商状态码 / 返回体分类规则见该模块顶部注释。
